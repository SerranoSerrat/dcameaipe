Chapter 1

1Get Started

Installation, and a first model end to end.

1.1Installation

dcameaipe isn't on CRAN yet — install the development version from GitHub:

# install.packages("remotes")
remotes::install_github("SerranoSerrat/dcameaipe")

One dependency is optional and only needed if you plan to absorb high-cardinality fixed effects: 

# only needed for Z_FE_absorb = TRUE
install.packages("fixest")

1.2What the function fits

dcame_aipe() fits a joint model in which each group gets its own flexible function of the treatment, g_k(D) — either a polynomial / B-spline basis selected by cross-validation (model = "basis", the default) or a penalized GAM smooth (model = "GAM"). Controls enter additively. For a continuous moderator, groups are formed by quantile bins (terciles by default) and the headline D-CAME and AIPE contrast the bottom and top bin.

Because no single coefficient summarizes a non-linear interaction, the function returns the estimands rather than a coefficient table: summary(res) gives one row per estimand and res$plot assembles the predicted values, the interactive partial effects, and the estimand comparison into a single figure. See Theory in Short for what those quantities mean.

1.3A first example

Binary moderator, known functional form, robust standard errors:

library(dcameaipe)

res <- dcame_aipe(
  data        = DGP2,
  Y           = "Y", D = "D", X = "X",
  estimand    = "AIPE",
  user_spec_0 = 2,               # quadratic for X = 0
  user_spec_1 = 3,               # cubic for X = 1
  inference   = "regular",
  vce         = "robust",
  compare     = "ALL"          # linear model, D-CAME and AIPE together
)

summary(res)   # data.frame of all estimands
res$plot        # combined PV / IPE / estimand plot

Continuous moderator, fixed effects, survey weights and a cluster bootstrap — the specification used in the paper's application: 

res2 <- dcame_aipe(
  data      = robots,
  Y         = "immig",
  D         = "iv_d13_indshock_fo_std",   # continuous treatment
  X         = "education",               # continuous moderator
  Z         = c("age", "female"),
  Z_FE      = c("nuts", "cntry_year"),
  wgt       = "pspwght",
  estimand  = "AIPE",
  compare   = "ALL",
  model     = "GAM",
  smooth    = "GCV",
  hist_pv   = "rug_1000",
  inference = "bootstrap", B_boot = 500,
  vce       = "cluster", cluster = "nuts2_year"
)

1.4Key arguments

  • Y, D, X — outcome, continuous treatment, moderator (binary or continuous)
  • Z, Z_FE — additive controls and fixed effects; Z_FE_absorb = TRUE routes high-cardinality FE through fixest::feols()
  • estimand — "DCAME" or "AIPE" (required)
  • compare — "LINEAR", "DCAME", "AIPE", or "ALL" to put all three on one plot
  • model — "basis" (poly/B-spline with CV selection, default) or "GAM" (mgcv penalized smooth)
  • user_spec_0, user_spec_1 — impose a known polynomial degree per group instead of selecting one
  • smooth — "REML" or "GCV" for the GAM smoothing parameter
  • inference — "crossfit", "bootstrap" (with B_boot), or "regular"
  • vce, cluster — "robust" or "cluster" standard errors
  • wgt — survey or sampling weights
  • hist_pv — rug/histogram overlay on the predicted-values panel, e.g. "rug_1000"
Which inference option? When the functional form is selected from the data, the standard errors have to account for that first step. "crossfit" splits the sample so that selection and estimation use independent data; "bootstrap" re-selects the functional form inside every resample. Bootstrapping gets expensive as n grows; cross-fitting struggles when n is small, because splitting penalizes more complex functional forms. Use "regular" only when the functional form was fixed in advance (e.g. via user_spec_*).

See ?dcame_aipe for the full argument list, or the package README.
